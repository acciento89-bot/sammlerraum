# Owned smart collections (Phase07 Task3A)

Smart collections save a query, never matching item IDs or copied item rows. The version1 definition is `{version:1,text,filter,lifecycle}`, with a nullable typed ItemFilter. Empty text plus null filter explicitly selects all owned items. Name accepts 1–100 UTF-16 units before and after NFKC/trim, valid Unicode and no control characters. Duplicate names are allowed.

The fresh authenticated actor owns every operation. `GET /api/v1/smart-collections` lists summaries using `limit` (20 default, 50 maximum) and `cursor`; summaries omit definitions. `POST` creates with strict JSON `{name,text?,f?:string|null,lifecycle?}`. `f` is the raw filter JSON string: the existing duplicate-member and complexity guards parse it directly. Omitted/null `f` means no filter. Text and filter retain the exact direct-search limits. Mutation bodies are bounded to32KiB including escaping and decoded with fatal UTF-8. Unknown keys reject. Successful creation returns201 with the normalized detail.

`GET /api/v1/smart-collections/[id]` returns one normalized detail. `PATCH` fully replaces name/query and requires `expectedRevision`; omitted query fields reset to their defaults. `DELETE` takes strict JSON `{expectedRevision}` and soft-deletes. Updates and deletes compare live owner/id/revision atomically and advance the revision; stale own edits conflict409, while foreign/missing/deleted IDs all return404. Revision2147483647 cannot advance. Malformed caller IDs return400. No restore or sharing is provided. Mutations require exact configured APP_ORIGIN. All responses use no-store and a request ID.

`GET /api/v1/smart-collections/[id]/items` accepts only `limit` and `cursor` and returns the exact owned SearchPage. Each resolution loads the live saved row/revision and validates current references, inventory, count and page inside one bounded RepeatableRead transaction. Saving/replacing likewise executes the actual query at limit1 in the mutation transaction to validate current references and availability. The existing12-second operation/5-second transaction/2-second statement budgets and recognized40001-only retries apply to both reads and writes; any error escapes the transaction and rolls back. A lost network outcome is not an assurance that a write did not commit or permission to retry it automatically.

List keysets order createdAt DESC/id DESC and preserve the exact total before cursor. Their canonical unsigned cursor binds owner/operation/limit. Item cursors additionally bind the stored query/saved ID/revision through the actual search seam. Direct-search/list/other saved ID/revision/limit replays fail400. Later pages see live state, with no retained database snapshot. Editing a query conservatively invalidates prior item cursors even for identical replacements.

Malformed stored definitions and currently unavailable saved references/capabilities resolve as409 SMART_COLLECTION_UNRESOLVABLE. Structurally valid unavailable definitions remain readable for editing; malformed raw bytes are never returned as fallback. Caller cursor errors remain400, dependency/budget errors503 and corrupt inventory/invariants500. Invalid new filter syntax is400 and new unavailable capability/reference422. Mutation oversize413 and encoded query oversize414 precede parsing. Output is bounded to1MiB and includes only normalized definitions or whitelisted search summaries, with no owner input or sensitive item payload.

The additive PostgreSQL migration enforces owner cascade, version1, positive bounded revision, basic envelope and32KiB JSONB text size. Reads enforce the actual typed AST schema rather than claiming the native CHECK repeats it. No item-membership relation exists. Full Phase07 Task2/Task3 acceptance remains open: legacy money/market/shared/duplicate relation producer integration and later UI remain separate gates. No production/provider or real-data change is included.
