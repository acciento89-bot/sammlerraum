# Media and Documents Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add secure item/profile/catalog media, private documents, persistent local storage, image processing, protected reads, and safe lifecycle cleanup.

**Architecture:** Domain records reference `MediaAsset`; bytes are accessed only through a `StorageProvider`. V1 uses local persistent storage. Upload verification happens before durable linking; image variants are worker jobs.

**Tech Stack:** Node fs/promises, Sharp, file-type, Prisma 7, pg-boss queue, Zod, Vitest.

**Spec:** `docs/superpowers/specs/2026-09-19-sammlerraum-design.md`

## Global Constraints

- Private documents are not public because their parent item is public.
- Original images remain stored; derived variants are separate assets/variants.
- Strip unnecessary EXIF including GPS from derived public images.
- Never trust filename extension or browser-supplied MIME alone.
- Cleanup deletes bytes only after all references and retention windows are cleared.

## Review Focus

1. Oversized/decompression-bomb images must be rejected before expensive variant fan-out.
2. A guessed media UUID must not bypass authorization.
3. Removing one link must not delete an asset still referenced elsewhere.
4. Partial upload/database failure must not leave permanently orphaned bytes.
5. Public derivative metadata must not leak original EXIF GPS.

- [ ] **Step 3: Implement storage interface**

export interface StorageProvider {
  put(key: string, bytes: Uint8Array): Promise<void>;
  read(key: string): Promise<Uint8Array>;
  delete(key: string): Promise<void>;
  exists(key: string): Promise<boolean>;
}
