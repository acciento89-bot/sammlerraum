# Staged import foundation

Phase08 Task1 persists import jobs, source rows and private reusable mapping profiles. Its service can create a pending upload intent, save a versioned profile, build a resumable preview and read a completed preview in bounded pages. It does not upload/parse a source file, expose an HTTP endpoint, write inventory, or provide the import UI. Those are subsequent tasks.

## Source and preview boundaries

The source key is generated by the server as `imports/<job UUID>/source` and is omitted from public-facing job DTOs. Source metadata is only a declaration until the actual uploader/parser verifies bytes and checksum. `AWAITING_UPLOAD` cannot be previewed. Current hard safety ceilings are20MiB and10,000 source records; a row has at most256 string/null cells, each at most16KiB UTF-8, with at most64KiB compact JSON for the whole row. Parser configuration may lower these ceilings; raising them requires matching contract/database review. XLSX handling must preserve numeric XML lexemes and must not convert large exact values through IEEE-754 numbers or infer money from cell display formatting.

Each job belongs to an authenticated owner and live owned collection. Every read/mutation rechecks that scope. Raw source identities are immutable through UPDATE; source row keys are unique and pinned to job/row number. Reusable profile updates use expected revisions. The first preview stores its own mapping snapshot and profile revision, so subsequent profile edits do not reinterpret it.

Preview generation processes at most100 rows per transaction and reports progress honestly. It does not become `REVIEW_READY` until every parsed row has been processed and all known source duplicates have been marked, including rows in earlier batches. Completed preview pages recheck whole-generation membership before LIMIT. A missing row or stale generation yields a closed integrity failure. A response exceeding2MiB is rejected rather than truncated; a caller can request a smaller batch/page. All writes use the existing bounded RepeatableRead/statement timeouts; a failed final update rolls back row previews and progress together.

## Interpretation and decisions

Column indices and date grammar are explicit. Item title/quantity and identifier normalization reuse existing policies. Canonical money uses the pinned M7 preview validator. Canonical RAW requires explicit scale/unit columns and its source contract; historical RAW remains explicitly UNKNOWN. Blank optional monetary input is no value, not CLEAR. Explicit zero is a value. Invalid fields become structured row errors with SKIP as their only action.

Exact normalized identifiers are matched only against live owned items in the selected collection. A valid unmatched row offers CREATE/SKIP; an existing match offers SKIP/MERGE/CREATE_SEPARATE. Source-only duplicates offer SKIP/CREATE_SEPARATE because no existing merge target exists yet. No action is silently selected, and previewing never mutates inventory. Duplicate candidates/response bytes are bounded; an over-budget result is refused, not shortened.

Task3 must persist the explicit row decision and perform actual writer authorization/CAS atomically with the row commit receipt. A MERGE must retain fields not explicitly selected for replacement. Prospective create defaults and absent mapped values are not permission to overwrite existing quantity, money or dates. Monetary MERGE requires a target-bound replacement preview/precondition; the prospective NEW receipt is not itself authority to overwrite a target. Source and row identities alone do not claim retry-safe inventory commits before this producer exists.

## Database and validation notes

The additive staged-import migration introduces only the three new tables, their enums, constraints and source identity guards. A second additive migration aligns PostgreSQL's automatically truncated index name with Prisma's naming convention; the first migration was already exercised and is preserved unchanged. Source keys/files need explicit cleanup integration before upload APIs are enabled. The parser must not populate preview state from unverified bytes or execute spreadsheet formulas/macros.

Profile-name mutations advance the owner's database row version while retaining its visible fields. This serializes concurrent name checks and forces stale RepeatableRead contenders to retry; merely locking an unchanged parent would leave their old snapshots usable. Native tests use separate database clients for this race. All current data/tests are synthetic and owned; no production migration, provider, mail or purchase action is performed.

## Bounded source parser (Phase08 Task2)

The internal worker handler `imports.parse-source` takes only a job ID. It derives the current owner, live target collection, generated private source key, declared bytes/checksum and pinned versioned parser options from the database. The actual local-storage read is bounded before allocating the source; that same private buffer must match both byte count and SHA-256 before PARSING. Source declarations alone never verify an upload.

Server ceilings are `IMPORT_MAX_BYTES=20971520` and `IMPORT_MAX_ROWS=10000`. Configuration may lower them, not raise them. CSV is explicit-delimiter UTF-8 with preserved string values; XLSX is a bounded ZIP/SAX cached-value reader with no formula engine or display-style scale inference. It rejects macro-enabled/encrypted files, external relationships, DTDs, invalid coordinates, ambiguous sheets and malformed shared-string references. Select a named worksheet when a workbook contains several. Unsupported workbooks fail rather than guess.

XLSX ceilings:2,048entries,16MiB per decoded part,64MiB total declared decoded entries,100,000shared strings,64XML depth. Consumed entries also validate actual decoded size and CRC. Both formats enforce256cells,16KiB UTF-8 per cell and64KiB compact raw row JSON. Scanned blank records count toward the work limit. Original record/worksheet row addresses are retained separately from stable logical row keys.

The worker uses a90second fenced lease,10second heartbeat,60second cancellation deadline and at most5durable attempts. A read that ignores cancellation retains ownership until it actually settles. Batches contain at most100rows; replay compares existing immutable cells/addresses and cannot overwrite the prefix. Complete membership and final row count are required for PARSED. Late malformed input leaves FAILED, never a complete preview. Transient errors release the claim then reject to trigger broker retry; exhausted attempts close explicitly. No inventory is changed by parsing.

This is an internal producer, not an enabled HTTP uploader. Upload validation, dispatch initiation, source retention/deletion and localized UI remain later integration work and must be completed before exposing uploads. Keep [parser license notices](licenses/import-parser.txt) alongside any distributed bundled worker; dependencies are pinned in the lockfile.

## Explicit inventory commit (Phase08 Task3)

The internal `imports.commit` handler consumes only an approved job ID. Before approval every source row needs an explicit legal decision; invalid rows can only be skipped. A merge names one current owned target from the exact preview matches, a server-generated current-target token and the specific mapped fields to replace. Blank optional values and unmapped defaults do not clear or replace existing fields. More than one merge into the same target is refused; resolve the additional source rows explicitly.

Approval freezes mapping/generation and decisions. Each ten-row transaction includes the existing item/identifier/money authority, immutable row result and job progress. Duplicate deliveries serialize on actual job/collection locks. Monetary replacement pins both the original row interpretation and a target-bound M7 replacement preview/fact token. Canonical and UNKNOWN meaning are never interchanged. Changed targets, new external identifier conflicts or changed money generations close rather than choose another target.

Completed retries validate whole membership and all bounded receipt pages before succeeding. Permanent conflicts mark FAILED only against the observed revision; completed chunks remain honestly counted and are not rewritten. Transient errors from both writing and recording failure receive a controlled broker retry message. No public source-upload/decision/commit route or localized UI is exposed by this internal service. The later API/dispatch integration must retain current server capability gates, ownership checks, cancellation, source cleanup and private result delivery. Duplicate delivery of an already-FAILED approved job currently consumes only the bounded broker retry allowance; later dispatcher policy must settle that minor without reopening the job.

## Private tabular export producer (Phase08 Task4)

The internal `requestExport` service creates an owned, validated CSV/XLSX intent. A durable dispatcher sends only the job UUID to `exports.build-tabular`; no caller-provided actor, rows, SQL or storage key is accepted. Actual public routes/download and UI are Task7 work, not delivered by this producer.

Owned full inventory, collection, real node subtree and current filtered search use the existing selection and M7 monetary authority in one bounded repeatable-read capture. Search pagination is never treated as the full export. The complete monetary outer scope is checked before matching for interpreted exports. Current caps remain1000items,8MiB frozen source,100identifiers per item,16KiB decoded cell,64KiB decoded row,16MiB worksheet and32MiB output. Oversized values fail; they are not truncated. Default RAW values retain exact digits and UNKNOWN meaning. INTERPRETED requires trusted server capability and explicit completeness policy. No conversion or exponent is inferred. DE/EN headings and the source timestamp accompany canonical values.

Private notes and physical locations are omitted by default; the two explicit opt-ins are frozen into the intent and snapshot. Document bytes, policy references and arbitrary item objects are never queried or serialized. Every output attempt is reserved as an owned DOCUMENT MediaAsset before storage I/O. Its generated key, checksum, size, claim token and status use the existing private lifecycle. A busy asset lock retries without waiting indefinitely. Cancellation retains actual storage ownership until I/O settles; an aborted write cannot become READY. Publication rechecks current scope and source meaning in its transaction and fails on changed/erased data rather than replacing the immutable snapshot. Failed attempts remain known to normal media cleanup; deleting the current artifact cascades its job/source. Explicit expiry and authenticated delivery checks remain mandatory Task7 integration work.

CSV profile `sammlerraum.tabular.v1` uses UTF-8 BOM, quoted RFC-style cells and `APOSTROPHE_PREFIX_V1`: every data field except the two schema markers has exactly one extra leading apostrophe. This keeps numeric identifiers, large integers, formula-looking text and existing apostrophes distinguishable. The explicit `SAMMLERRAUM_TABULAR_V1` reader profile validates markers and removes exactly one transport prefix; GENERIC import never guesses or strips it. This is a defined file encoding, not a promise that arbitrary spreadsheet edits/re-saves are safe. XLSX uses `XLSX_LITERAL_V1`, literal inline strings without formulas, bounded ZIP32 and SpreadsheetML ST_Xstring escapes. Its reader decodes those escapes once, including literal `_xHHHH_`, CR and surrogate pairs. External spreadsheet changes can invalidate the profile and must not be silently guessed.

## Connected private workflow (Phase08 Task7)

The foundation sections above describe the stages in which the feature was built. The current source connects them through authenticated `/api/v1/imports/{operation}` routes and the localized imports, exports and insurance screens. Deployment remains a separate release decision.

Actual uploads use multipart `metadata` plus one file, with a 20 MiB source cap and a finite multipart overhead. Fresh authenticated ownership and exact same-origin checks precede body processing. The server generates the job/source key, observes actual bytes and SHA-256, persists the cleanup manifest before storage I/O, and enables parsing only after the physical write settles. A client-generated upload request UUID makes an unchanged retry idempotent; changing its file, target or options is a conflict. There are at most three active jobs and twenty retained source jobs per owner. Profile lists use bounded keyset pages; preview pins the saved profile revision rather than following future edits.

The one worker runtime polls durable uploaded/approved job intents and enqueues only fixed internal task names with job IDs. Preview never changes inventory. Every row needs a saved explicit decision; MERGE requires a current target and named replacement fields. Monetary approval requires the affirmative server `MONEY_AUTHORING_ENABLED` capability; there is no inferred currency or fallback to weaker monetary meaning. Operationally drain already-approved work before disabling authoring. Source parsing, source upload and source erasure share the same PostgreSQL-backed source lock.

An unapproved job can be cancelled from its current revision. Cancellation invalidates parser ownership and schedules exact-source cleanup; it does not roll back inventory. Once approval is recorded, even a later permanently failed job cannot be cancelled. The screen reports processed data rows (including skipped rows); a failed approved import may retain an already committed prefix. Inspect inventory before deciding whether to create a different import.

Sources expire after 24 hours. `ImportSourceObject` contains only the internal UUID/key/deadlines and cleanup markers, survives parent/job deletion, and permits bounded cleanup without scanning arbitrary files. Cancellation makes an unapproved source immediately eligible. Active parser I/O and a live committing job remain protected until settlement. Known-key tombstones have no arbitrary expiry, so a very late write to an already deleted known key can still be reconciled. Original source rows and preview snapshots are removed with the job; existing inventory and unrelated files are untouched.

Exports and PDF reports have authenticated owner-only keyset history and protected downloads. Download validation checks current scope, generated key, media state, expiry, size and SHA-256 under the existing media lock. No storage path or signed public URL is exposed. Downloads represent their captured timestamp; ordinary subsequent edits do not silently regenerate their content. An expired job/source snapshot is removed by the existing cleanup loop; only its exact, unlinked attempt artifacts become eligible for normal media deletion. Explicitly linked item documents are retained with the item.

The insurance editor saves a separate exact collection-total or per-unit record with revision preconditions. Every optional PDF field starts off. Proof selection lists only current owned READY linked documents in the selected collection, paged by asset ID; at most twenty may be selected, within the shared 16 MiB image/proof budget. Choosing proofs without selecting a document cannot queue a report. Neither insurance records nor PDF output are independent appraisals. Unknown outcomes require reading current status before another user decision; the UI never automatically replays a mutation because a following read failed.
