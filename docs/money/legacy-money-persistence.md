# Legacy money persistence (M2)

This is the native storage and single-fact service layer, not the completed money cutover. Existing raw CRUD still authors no scale evidence; M3–M7 provide the versioned writers, routes, UX, bounded consumers and captured valuation facts. No production inventory, classification, backfill or rollout is performed here.

## Stored facts and interpretation

The additive migration leaves existing purchase/custom raw pairs and catalog snapshot JSON unchanged. Existing present personal facts have the logical all-zero generation until their first raw write; no event or interpretation is invented. Equal raw writes rotate a server-assigned UUID. Ordinary custom-value deletion appends a durable missing tombstone; deleting its actual item/definition removes personal history rather than resurrecting absence. A previous classification of a logical baseline remains queryable and is not hidden by a later BASELINE.

Three family-specific event tables bind purchase item, custom item+definition, or immutable catalog revision+target+definition. Subject sequences are durable across generations. Events carry raw facts, optional meaning, and flattened original lineage. A copied assertion is not independent evidence. Revoking an original assertion, erasing its human evidence or deleting its original personal subject makes surviving copies UNKNOWN. Deleting an intermediate copy preserves the still-live original assertion.

AUTHOR means the actual pinned prospective authoring receipt has been revalidated against currency, exponent, authority hash, unit and raw amount. CLASSIFY is a labelled owner attestation or persisted-operator decision; its offline reference is not fetched or presented as machine verification. Unsupported declarations retain an assertion-specific unit and remain ineligible for cross-fact arithmetic. Native constraints bound receipts to 2048 serialized bytes and protect shape; the domain additionally revalidates semantic policy before returning ELIGIBLE. Missing and malformed facts are never conflated.

## Transaction and authority boundary

Store functions use a caller-owned active transaction and never open one. Private mutation locks the actual owned live item and owned live collection; custom definitions must belong to that collection and still be MONEY. Canonical mutation requires the existing persisted moderator/admin authority before locking the catalog entry. That role grants no access to another person's private facts. Application sessions, route origin checks and whole-operation budgets remain the surrounding service's responsibility.

`requireMoneyToken` authorizes first, then bounded-decodes a canonical equality token and compares it to a fresh single-statement fact/origin/revocation read. Tokens are not credentials. Resolved facts cannot cross transaction/actor boundaries and are refreshed before assertions or copying. The token includes actual origin evidence-erasure time, separately from physical origin identity and revocation identity. An older assertion can be revoked using its own historical precondition after the current raw generation has changed.

A PostgreSQL row lock alone does not refresh an already established RepeatableRead snapshot. Metadata inserts therefore update the parent's MVCC tuple with `id=id`, changing no domain field, timestamp, raw pair or generation. A concurrent stale reader is retried through the existing serialization boundary and then receives a conflict. Raw purchase writes already change their parent; a BASELINE running inside their BEFORE trigger must not touch it recursively. Custom raw writes update the parent tuple independently. ReadCommitted callers remain supported without nested transactions or forced isolation. New COPY insertion requires a fresh raw-only destination, so an unknown source cannot silently retain unrelated interpreted target meaning.

## Immutability and privacy

Normal edits cannot change an event's raw amount/currency, operation, meaning, receipt, identity, sequence or recording time. Only one-way actual metadata erasure and genuine FK nulling after the referenced row is gone are accepted. Explicit self-erasure rejects a different target actor. AUTHOR actor-only removal preserves the nonidentifying prospective receipt; CLASSIFY human-evidence erasure invalidates dependent interpretation. Erasure returns only bounded aggregate counts internally, not all erased IDs.

Personal event parent FKs are SQL-owned DEFERRABLE INITIALLY DEFERRED. This is needed for the actual combination of User→actor SET NULL and User→item→event CASCADE; an immediate parent FK otherwise rejects an intermediate cascade state. Native tests explicitly force all deferred constraints immediate before fixture rollback. Prisma models express the relationships, while custom trigger/check/deferrability behavior remains in the migration. Catalog history uses restrictive immutable revision/definition references. Proposal and rollback money envelopes are initially nullable; submitted proposal patch/envelopes and rollback money payloads are immutable.

## Verification boundary

Synthetic PostgreSQL 17.11 `_test` schemas replay real migrations; helpers reject production and caller-selected schemas. Native tests exercise actual SQL writers, FK actions, raw/event atomic rollback and immutable metadata transitions. Prisma integration tests exercise authorization-before-token, raw ABA, concurrent classification, original revocation after replacement, custom absence/reinsert, erased evidence, actual ReadCommitted operation and receipt-policy rejection. The ordinary pure suite keeps native cases visibly skipped unless explicitly enabled; CI has an explicit native allowlist for both new database suites. No test makes a payment, contacts an evidence provider or classifies real data.
