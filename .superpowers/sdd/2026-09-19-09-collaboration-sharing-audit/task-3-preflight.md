# Task3 preflight — explicit granular sharing

Approved Phase09 Task3/spec§6 authority; no implementation while Task2's broad native gate owns runtime. Collection/node/item scopes; public high-entropy token or registered-user grants, separate from memberships. Hash-only tokens; optional cryptographic PIN hash; expiry/revocation immediate. Default excludes all private notes, storage locations, insurance and purchase receipts. Default financial values excluded, including custom MONEY fields, so no accidental backdoor through another projection. Read-only grants never add roles or authorize writes even for an existing Viewer.

Projection must be an explicit field whitelist from the actual authorized scope, bounded/paginated and current. Never pass a token holder as a fake Owner to an edit/financial authoring service. Public visibility/ancestor policies remain unchanged; an explicit Owner-selected private share is a deliberate additional read grant, not public promotion of an entire parent. No outside-scope breadcrumbs, sibling data, storage keys, internal owner/actor IDs, PIN/token hashes or document URLs in projected output. Images, monetary values, individually selected DocumentLink IDs and exports require their own flags. Selected purchase receipts additionally need explicit receipt permission. No general edit permission exists.

Current model protected documents are Owner-only; share delivery needs its own real explicit grant path, never an unconditional weakening of existing document.view. Document/image bytes proxy through current authorization checks before/after actual storage reads; no irrevocable signed private URL. Missing/unlinked/deleted/outside-scope proof stops access. Noindex/no-store/referrer restrictions for bearer views; never log bearer/PIN data. PIN derivation outside SQL locks with bounded input; revalidate immutable share revision/state under a fresh bounded transaction afterwards.

Transfer revokes old ownership-bound shares, permanently, rather than letting bearer permissions follow new private ownership or resurrect on a round trip. Actual root/source scope, recipient identity, live parent/items and ownership rechecked every resolution; parent/item deletion or membership loss cannot leave a broader edit path. Registered recipient account deletion cascades its private grants; creator identity/audit semantics respect later account erasure. New migration only;030000–036000+040000 all frozen/applied.

Required REDs: defaults/expiry/PIN/revocation, recipient isolation, Viewer remains read-only, node subtree without siblings/private ancestor escape, selected documents and all default financial exclusions, transfer revocation and actual delivery revocation during reads, bounded pages/export. UI/resources remain existing localized architecture; no provider activation/deployment or real user sharing.
