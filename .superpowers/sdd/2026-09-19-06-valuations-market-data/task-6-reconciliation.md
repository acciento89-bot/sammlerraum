## Concrete remaining gaps from actual error/lifecycle code

**Provider failure classification.** Current handler acknowledges only known `MarketDataError` and `MarketSyncConflict`; all other errors become fresh sanitized `MARKET_SYNC_RETRY` or `MARKET_SYNC_INTERRUPTED`. Therefore the preflight's terminal malformed mapping/unsupported response/auth denial behavior does not exist for future adapters yet. Do not import domain errors into market-data to force it.

Recommended minimum: export a small market-data-owned typed failure with an allowlisted constant code and retryability, no arbitrary provider message/cause/body. Handler recognizes that class, acknowledges terminal codes with fixed sanitized log text and converts retryable/unknown exceptions to existing broker-safe errors. Abort still wins. Adapter tests classify invalid mapping/permanent denial/malformed selected data as terminal; transient transport/429/5xx/permit contention remain bounded retry. This is a narrow worker/adapter contract, not a generic error framework. Alternative is retaining up to three harmless retries for all adapter errors, but that conflicts with the approved preflight's terminal intent and burns call budgets for known permanent failures.

**Permit cleanup and drain are separate from handler settlement.** Runtime `stop()` synchronously marks stopping/aborts its controller, then awaits dispatcher and `Promise.allSettled([...pending])`, with a15s rejection timeout. Worker main catches that rejection, continues independent cleanup and queue stop, and deliberately does not disconnect DB if market stop failed. This correctly avoids equating timeout with cancellation. However a future permit can finish HTTP, fail its compare-and-clear, throw, and leave a durable blocked claim; its handler promise is now settled, so current `allSettled` alone will consider the runtime drained. A failure from earlier completed work has already been removed from `pending` as well.

Recommended minimum: optional worker-owned request lifecycle hook on `composeMarketSync`, e.g. `requestLifecycle?:{stop():Promise<void>}`. The real permit owns tracked attempts plus latched uncertain/cleanup-failure state; its idempotent stop synchronously closes admission/aborts local wait/send work, awaits actual transport and cooldown cleanup, and rejects if uncertainty or unresolved local claims remain. `composeMarketSync.stop()` starts this hook with controller abort and includes its promise in the already bounded market stop aggregate. Main's existing no-DB-disconnect-on-market-failure guard then applies. Fake/legacy compositions omit it. Never detach cooldown or use an always-rejecting handler promise as a substitute for tracked physical settlement.

A durable claim left by another process must also fail activation/recovery checks until authorized verified fleet drain; a locally successful stop is not fleet-wide license-purge authorization. Gate release after a settled transport can be safe for spacing yet still fail operational cleanup—report those separately. No auto-clear on startup or shutdown. If the transport ignores cancellation, keep the claim, let the existing stop deadline reject, and do not claim safe drain or disconnect DB beneath work.

The approved 1s monotonic cooldown after complete transport settlement remains within each awaited permit promise. Its DB compare-and-clear must get an independent bounded cleanup opportunity even when request signal is aborted; otherwise every ordinary shutdown would abandon safe-to-release claims. The request signal prevents new HTTP, but must not skip required settlement/cooldown bookkeeping. Cleanup failure stays latched. Verify total worst-case acquisition/SQL/abort/cleanup behavior against runtime15s; do not increase limits or promise success merely from nominal timeout sums. Existing fail-closed shutdown is preferable to a false numerical guarantee.

New integration proof: release fails after HTTP settlement, handler rejects and is removed from the pending set, later runtime stop still rejects via lifecycle hook; main does not disconnect DB. Also verify normal abort waits for body cancellation, cooldown and compare-and-clear before successful stop, ignored abort fails closed, no request starts after stop, and concurrent stop callers share completion. Real separate-client PG claim/budget/crash tests remain those approved in preflight, not a new model.
