## Actual contracts and proposed additions

Committed `packages/market-data/src/types.ts` has `fetch(request): Promise<MarketObservation[]>`, no signal or permit. `ProviderRegistry` accepts at most100 registrations, each one provider ID plus one namespace/type, and exposes only `get(id)`; no enumeration. It captures/binds the fetch method. Task3's approved optional cancellation context and `MarketRequestPermit.run({credentialKey,signal}, send)` are proposals until its reviewed commit. Recheck context forwarding through the registry and actual worker composition after Task3.

Task2 request is `{pollId,target:{entryId,variantId,revision,identifierId,namespace,identifierType,externalId}}`; it contains no private item data or product title. `prepareFetchRequest` authors the exact current mapping; `recordObservationsInTransaction` revalidates it, including empty batches, under the owning receipt transaction. `recordObservations` is the independent wrapper. `RecordResult.ids.length` is deduplicated count. No adapter repeats catalog matching or ingestion.

Every output keeps `externalId === request.target.externalId`, `identity:{mode:"POLL"}`, explicit metric, native bigint money, and `time:{basis:"FETCH",precision:"MILLISECOND"}`. No event ID, sale date, sample size or SOURCE timestamp is invented. Task2 allows 0..100 observations, 256-byte external ID, 64-byte metric, at most16 qualifiers/1024 JSONB bytes, 128-byte qualifier values, 512-byte sourceReference, 4096 combined metadata bytes and 262144 normalized batch bytes. Adapters reject before exceeding any bound; they never truncate a price batch into apparently complete success.

Factory proposal: `makeScrydexProvider({credentials,transport,permit,clock,money,policy})` and `makePriceChartingProvider(...)`, returning only `MarketDataProvider`; dependencies have narrow interfaces. Transport reads bounded raw UTF-8 bytes, accepts AbortSignal, refuses redirects, and returns status plus received-at captured after the bounded body settles. Credentials remain factory-private. No SDK automatic retry/redirect/pagination may bypass the injected permit. Domain already depends on market-data; market-data must not import domain back. Inject a small money capability from worker composition: `parseMajorUnits(canonicalDecimal,currency):bigint` and `validateMinorUnits(amount,currency):bigint`, implemented with existing exported Money parser/limit. The worker may validate currency using `parseLocalizedMoney("0","en",currency)` and normalize trailing fractional zeroes before the existing parser; no new currency-table export is necessary. Add adapter package exports/worker dependency only when needed after GO.

**Response-time seam requiring root ruling:** callback `context.reportFetchedAt?: (isoUtcMilliseconds:string)=>void`, alongside approved signal, is the smallest proposed way to preserve body-receipt time through the existing array return. Handler creates the callback, accepts one successful HTTP response timestamp, validates it, and uses it for ingestion/receipt only after successful output validation; legacy fake providers retain post-fetch clock fallback. A production adapter must report it. Callback fires after the bounded HTTP-success body completes, before decoding/cooldown; a later decode failure never creates a receipt. For this single-response scope there is no pagination ambiguity. Do not mark this retrieval time SOURCE. Without a reviewed seam, document post-fetch completion semantics explicitly and do not claim exact response time.

## Exact mapping and intentionally bounded coverage

Use canonical compact JSON-array strings as catalog identifier values, parsed with strict fixed arity and round-trip equality to `JSON.stringify(decoded)`, maximum256 UTF-8 bytes. No extra keys, whitespace aliases, control characters, invalid Unicode, URLs, escape aliases or fallback interpretation. Reject malformed mappings before permit/network. Existing catalog identifiers can hold these values; no catalog schema extension is necessary.

| Provider registration | Canonical identifier example | Binding rules |
| --- | --- | --- |
| `scrydex`, namespace `scrydex`, type `pokemon_card_variant` | `["v1","pokemon","base1-4","unlimitedHolofoil"]` | Card ID ASCII `[A-Za-z0-9_-]{1,64}`; variant name exact nonempty string <=128 bytes; full encoding <=256. Require non-null catalog variant explicitly bound by this identifier. Response card ID must equal selected card and exactly one variant name must equal selected name. ID+category+console are explicitly curated catalog facts. Response ID and console-name must match exactly. Entry-level or variant-level binding is precisely the persisted target; no automatic rebinding. |

Scrydex target represents a print variant. Raw condition, company, grade and flags are source qualifiers within that target, not a translation into a personal item's condition/grade. A catalog requiring a grade-specific target needs a later explicit selector contract; this version does not infer that mapping. PriceCharting category comes from the approved identifier, never guessed from field names, title or a loose genre substring. Cross-category/missing-console mismatch is terminal.

Scrydex success requires the documented single-card envelope established at GO, exact selected variant, and an actual prices array (including explicit empty). Missing prices is malformed, not an empty success. Bound variants <=32 and selected price records <=25; process all selected records and allowlisted metrics, rejecting output >100. Unsupported type/qualifier shape fails the selected response; absent individual metric/null means no observation for that metric. Do not silently convert a missing selected variant to [] or merge variants.

PriceCharting GET uses only `/api/product` with configured token and decoded exact ID. Successful status plus matching ID/console is mandatory. Missing all supported price fields yields explicit no-data [] only when the authenticated success envelope is otherwise valid. No Marketplace, CSV, history, search or pagination calls.

Recommendation: narrow Task6's original UPC/query wording to explicit unsupported ingestion paths. Optional candidate resolution would be a separate bounded helper using `/api/product?upc=...` or `/api/products?q=...`, returning at most20 candidates and never observations, followed by explicit catalog product-ID approval. It adds another paid-call surface and approval workflow, so defer it. This avoids pretending best-match text is an exact identity while retaining a documented later path.

Card company remains unspecified except PSA10; do not assign PSA to every card field. For both adapters confidence is optional fixed sourceLabel plus short methodology identifying a provider guide statistic, never a numeric confidence score. No source sampleSize from unrelated annual volume.

Scrydex currency must be explicit supported ISO currency and uses the existing `currencyMinorUnitExponent`. PriceCharting is deliberately a USD guide-only profile; activation must verify the purchased guide's USD denomination (API examples show dollar pennies but not a per-response currency key). Do not generalize that assumption to other guide currencies. No FX conversion. Use existing `MAX_AMOUNT_MINOR=9223372036854775807n` and currency table; do not copy a second table.

Read the body once as text; never use Response.json or JSON.parse then String(number) for money. Preferred decoder wraps every numeric primitive in a private branded `{lexeme}` using reviver context.source; later schemas explicitly consume brands. Strings remain distinct from numeric tokens. A local narrow signature assertion handles ES2023 typings without widening project lib or suppressing type checking. Capability check parses a known unsafe integer and confirms exact source, otherwise factory fails closed. Validate original grammar; PriceCharting amount tokens must be nonnegative decimal integers, Scrydex tokens nonnegative plain decimal. Reject exponent notation, signs including -0, NaN/Infinity, coercions, unsafe already-decoded fake client values, and tokens >80 characters. Decimal strings may be supported only by an explicit documented schema, not automatic coercion.

For Scrydex, split decimal text, remove only redundant trailing fractional zeroes, require remaining fraction length <= currency exponent, pad and construct bigint. Thus USD 1.230 is exactly123n; USD1.231 fails; JPY100.0 is exactly100n; JPY100.1 fails. No rounding. PriceCharting integer pennies convert directly to bigint and never multiply by100. Oversize money rejects the entire batch. Reviver duplicate-key last-wins behavior is a known JSON semantic; do not claim duplicate-key rejection unless a later schema/security requirement justifies a tokenizer. Bound input to256KiB and decoded tree depth32/node count10000; catch parse/traversal failure as a constant invalid-response code. No generic parser dependency is required for this proposal.

Zero policy: exact zero is not missing, but whether a provider means unavailable is unproven. Recommended conservative adapter result skips zero with a bounded zero-omitted diagnostic count; no zero observation is ingested until provider semantics are documented. Null/absent metrics are omitted; empty strings, booleans, negative or malformed amounts are errors. This deliberate coverage cost needs root approval and tests; do not claim source zero means zero value or silently rewrite it to a positive number.

SourceReference is a short safe constructed provider/product/variant reference. Scrydex sourceUrl is omitted until a licensed canonical public detail path is verified. PriceCharting may use `https://www.pricecharting.com/game/<id>` under display permission. Never retain an API request URL, token query, response error text, headers or raw body. Task2's sourceUrl requires canonical HTTPS with no credentials, query or fragment. Errors exposed to broker/logs contain only allowlisted provider ID and constant code; explicitly suppress exception cause/stack and fetch URL instrumentation.

## Shared credential permit: concrete fail-closed PostgreSQL design

Reject a per-object sleep, future-start reservation, queue singleton or expiring lease as proof of actual HTTP spacing. A paused process can start after its reservation, and another replica can start beside it. A transaction held across a long HTTP callback is also unnecessary.

Recommended smallest durable state is one `MarketRequestGate` row per credential fingerprint, containing provider scope, activeAttempt UUID/null, acquiredAt, blocked reason, rolling/fixed budget counters and policy version. Stable key is SHA256 of a length-delimited provider scope and exact token bytes (Scrydex additionally team ID). Never use an operator-chosen alias that can differ across replicas. Do not persist token or expose fingerprint in jobs/logs. Rotation to a new token creates a new scope; reconnecting the same token reuses its blocked/budget state. All users of that token must route through this same database gate; other services sharing it invalidate the guarantee and block activation.

Admission is a short transaction: lock the credential row; check enabled policy and unchanged finite budget policy; if activeAttempt exists, return unavailable without stealing it; if call budget permits, increment attempted-call counters and set random activeAttempt; commit before any HTTP. Count uncertain sends, failures and cancelled-before-send reservations conservatively, with no refund. Missing row/policy, DB failure or budget exhaustion yields no send. Native constraints bound counters and require coherent active state. A public-only observation purge must not accidentally delete this operational gate and permit a still-active old sender.

The owning permit checks cancellation and calls the supplied single-attempt callback at most once. Callback is synchronous-start asynchronous-settle transport work: it may not schedule an untracked future send or retry. Keep the durable claim through complete response/error/body-abort settlement. Then wait at least1000ms measured by a monotonic clock after settlement, and only then clear by `WHERE activeAttempt = ownAttempt`. Clear failure leaves it blocked. This is conservative: next admission occurs after previous completion+1s, so next actual start is necessarily at least1s after previous start. The timer is not the global lock; the durable non-stealable claim is. Host/DB wall-clock jumps cannot shorten the monotonic cooldown. A process resuming late still owns the claim and prevents a successor; no preassigned start deadline is treated as an actual start.

Crash, lost connection after admission, ambiguous commit, ignored abort or failed cleanup leaves a non-expiring active claim. No TTL, heartbeat expiry, restart cleanup or automatic takeover can clear it. Recovery requires disabling all credential consumers, proving queued/manual replay and old processes drained/terminated, waiting any outstanding transport uncertainty out, and authorized compare-and-clear of that exact attempt. If drain cannot be proved, stay blocked. This buys safety at the cost of provider availability and operator recovery after crashes; an automatically recoverable distributed sender would need a stronger dedicated egress/fencing architecture, outside this task.

Permit receives `{credentialKey,signal}` through the approved Task3 seam and owns budget policy, DB access, clocks and settlement tracking. It returns only after callback and cooldown cleanup; on abort it still awaits actual transport settlement and cooldown before releasing. No catalog/receipt/admission lock is held over HTTP. DB connection acquisition, statement/lock/transaction timeouts are separately bounded. Suggested maxima: admission wait2s, HTTP including body5s, post-settlement cooldown1s, DB cleanup1s; no numeric overall shutdown promise until real driver acquisition and transport abort bounds are verified with Task3. Exhausted admission retry throws a sanitized transient code; finite queue retry remains Task3's policy. A timeout does not prove transport cancellation.

One high-level fetch makes exactly one HTTP attempt: pages1, redirects0, adapter retries0. Queue retry creates a fresh permit attempt for the same durable poll. Any later retry/page expansion must individually pass the permit and decrease the same finite budget; no wrapper around an entire paginated fetch is acceptable. 429/5xx/transport errors remain bounded queue retry; authentication/invalid mapping/permanent malformed response are terminal. Do not sleep arbitrary Retry-After values inside a worker.

Default production budgets are zero; positive explicit operator limits required, bounded by hard implementation maxima (proposal 60/hour and500/day per token, reductions allowed). Counters use DB UTC windows with non-regressing stored period keys; clock anomaly fails closed rather than resetting repeatedly. These are attempted-call caps, not a money guarantee. Scrydex activation additionally requires a documented conservative per-request credit ceiling, plan/overage control and corresponding budget, because delayed usage telemetry cannot establish spend limits. Do not build a billing/license framework to fabricate this proof.

## Root decisions and activation gates

Existing approved decisions retained: exact target and immutable receipt, optional cancellable worker seam, bounded default-off producer, explicit verified drain-before-purge/reactivation (no activation-generation subsystem). Costs remain delayed eventual refresh and no protection from privileged deliberate reimport of an old saved payload.

New proposed rulings needing root resolution before Task6 GO:

1. Approve canonical explicit variant/category identifier encodings and narrow Pokémon/card+video-game coverage; reject UPC/query ingestion and defer candidate helper. Cost curated mappings and reduced initial coverage; benefit exact Task2 compatibility without registry/schema expansion.
2. Approve conservative guide kinds and zero omission until documented semantics. Cost legitimate zero quotes omitted; benefit no false completed-sale or unavailable-as-zero claim.
3. Approve non-expiring per-token PG claim with post-settlement cooldown and explicit crash recovery. Cost one operational model/migration, reduced throughput and manual recovery; benefit actual cross-replica spacing without a false lease proof.
4. Approve/reconcile response receipt callback with finalized Task3 interfaces, bounded HTTP body transport and lexeme reviver capability check. Cost a narrow optional context addition and tests; benefit honest retrieval time and exact bigint values without a generic parser.

Production activation still requires verified credentials/subscription rights, explicit permitted storage/display/retention, finite request/credit policy, shared-token exclusivity, tested limiter and cancellation behavior, and authorized operational runbook/runner. The termination procedure must disable fetching AND reads on every replica, prevent new/queued/manual work, prove actual in-flight drain, purge provider observations/receipts/caches under authorization, verify absence, and forbid old-poll replay before reactivation. Gate recovery and retention purge must be coordinated; deleting a claim while an old sender can resume is unsafe. Task6/Phase13 must test these mechanics before real activation. This preflight neither implements the runner nor authorizes license acceptance, purge, payment, accounts or real requests, and does not claim live-provider readiness.
