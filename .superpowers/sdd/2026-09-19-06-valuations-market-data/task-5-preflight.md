## 1. Intended result and recommendation

Add an owner-only DE/EN `/[locale]/items/[itemId]/values` page reached from the real item editor. Show a separate latest personal estimate, append-only per-unit personal history and external observation groups. Include an append form for ACTIVE items of any quantity. Archived/disposed history is readable, with no append controls. Foreign/deleted item or deleted parent stays hidden. Do not borrow the parent item's public fallback.

Use one server privacy gate and one client controller consuming the finalized Task4 endpoint. Keep private notes out of route/query strings, storage, logs and public serializers. No chart, synthetic trend, quantity multiplication, FX, blended market number, source fallback, grading/condition conversion or extrapolated estimate. `aggregate` remains null. A group is not a comparable item price; its rows may have different metrics and qualifiers.

Recommended architecture: a dedicated page/controller plus small money, form, manual-history and source-history components. Embedding the whole feature in `ItemForm` would entangle it with unrelated purchase/custom-field parsing and refresh state. A read-only page would miss the required actual manual append journey. The dedicated route costs a navigation link and component files, but supplies a coherent boundary and bounded paging.

## 3. Exact money and input interpretation

### Stored history presentation

`formatValuationMoney({amountMinor,currency,minorUnitExponent}, locale)` validates the actual Task4 stored-money schema, parses decimal string with `BigInt`, and uses the **stored** exponent e. Compute divisor `10n ** BigInt(e)`, integer quotient and padded fractional remainder. Construct `Intl.NumberFormat(locale,{style:'currency',currency,currencyDisplay:'code',minimumFractionDigits:e,maximumFractionDigits:e})`; call `formatToParts` on the bigint integer quotient and replace only its `fraction` part with the exact remainder. For e=0 there is no decimal/fraction. Intl contributes grouping, decimal separator, code placement and spacing, never scale or monetary rounding. No `Number(amountMinor)`, division through Number, `parseFloat`, or ICU `maximumFractionDigits` inference. Explicit ISO code avoids ambiguous `$` and visually preserves currency separation.

The quotient is bigint even at MAX. All decimal digits, including zero/trailing zeros, survive. Read stored uppercase three-letter currency/exponent even if it is absent from today's new-write list; never call the current currency-membership helper on a historical response. The formatter is valuation-specific and requires exponent; it cannot accept a legacy `{amountMinor,currency}` object. Range rows format both endpoints exactly and repeat code or otherwise unambiguously label the shared currency. Do not turn missing/null into zero. Invalid response shape is a read error, not a blank price or inferred fallback.

Explicit expected digit sequences (currency code placement/locale whitespace follows Intl):

| Input minor / stored e | EN numeric output | DE numeric output |
|---|---|---|
| `0` / 2 | `0.00` | `0,00` |
| `100` AFN / 2 | `1.00` | `1,00` |
| `1001` IQD / 3 | `1.001` | `1,001` |
| `1` CLF or UYW / 4 | `0.0001` | `0,0001` |
| MAX / 0 | `9,223,372,036,854,775,807` | `9.223.372.036.854.775.807` |
| MAX / 2 | `92,233,720,368,547,758.07` | `92.233.720.368.547.758,07` |
| MAX / 3 | `9,223,372,036,854,775.807` | `9.223.372.036.854.775,807` |
| MAX / 4 | `922,337,203,685,477.5807` | `922.337.203.685.477,5807` |

Also prove historical scale wins when it differs from the current table, including a three-letter historical currency no longer writable. This is a presentation test, not license to bypass DB write constraints to fabricate historical rows.

### New manual append form

Fields: “Betrag pro Stück / Amount per unit”, “Währung / Currency”, time mode “Jetzt / Now” or “Früherer Zeitpunkt / Earlier time”, explicit date and time **UTC**, optional “Private Notiz / Private note”. Explain estimates apply to each unit; quantity is context only. Default currency EUR is a selectable convenience, not a fallback assigned to missing data. Zero is valid; empty amount is invalid. Do not prefill from purchase, market observations or latest estimate.

Use a text amount input, `inputMode="decimal"`, max80 characters. Offer exactly the canonical current numeric-exponent currency list. Help text gives locale-specific separators and 0/2/3/4 permitted decimal places; currency change retains text but requires fresh validation and preview under the selected currency. No automatic rounding or conversion. Parse with `parseLocalizedMoney` and send `.amountMinor.toString()`; omit exponent. Send only `{amountMinor,currency,observedAt?,note?}`. Show an exact formatted preview before submit. Locale grouping is accepted only according to the canonical parser; comma-or-dot legacy input rules do not leak here.

Default Now omits `observedAt`, allowing DB time after locks. Earlier time uses date + time inputs with millisecond support (`step=0.001`), both required together; validate canonical calendar values and build `YYYY-MM-DDTHH:mm:ss.sssZ` explicitly as UTC, preserving year0001..9999. Do not feed an unzoned `datetime-local` string to local-time `new Date`. Explain UTC; no DST/local-zone guessing. Server future-time validation is authoritative. Retain draft on validation failure.

Notes use Task4's trim/NUL/well-formed-Unicode/codepoint rules and display a codepoint counter after trim. Do not use HTML `maxLength=2000`, which excludes valid astral notes at half the limit. Use custom validation rather than another UTF16 ceiling that can reject otherwise valid trim-normalized input; the strict post-trim2000-codepoint rule is authoritative, alongside the finalized request byte limit. Escape notes and metadata as text, preserving authored line breaks. No HTML rendering or automatic translation of authored provenance.

### Language changes

Use route locale for labels, parsed input and persisted history formatting. Key controller/form by `{itemId,locale}` to prevent a preserved raw draft such as `1,234` silently changing from1.234 to1234. Within one mounted draft, capture `inputLocale` and never reparse raw text under another locale implicitly.

Add small page-local same-item DE/EN navigation so users can actually inspect this feature in either language. Clean state uses normal localized values links. Dirty draft presents an explicitly named “Entwurf verwerfen und Sprache wechseln / Discard draft and switch language” action; switching clears the draft and remounts, then re-fetches facts. No private draft goes into URL, localStorage or sessionStorage. Disable these local controls during submitting/unknown outcome; a user who otherwise leaves the page is not promised draft persistence. Existing shell home links retain their existing destinations; do not overhaul global routing. Test both the new same-item locale links and the actual shell-home behavior. Saved integer, currency, exponent and timestamps never change on locale switch.

## 4. Smallest honest legacy MONEY integration policy

This is a genuine pre-existing interpretation boundary, not a reason to guess a migration. Baseline `item-form-values.ts` uses ICU scale for purchase, personal custom MONEY, catalog MONEY input and `displayCustomFieldValue`. `catalog-facts.tsx` independently divides a safe integer by a Number scale and formats with ICU, risking fractional loss near the safe-number boundary. Server purchase/custom contracts accept a nonnegative safe JS integer plus runtime-supported currency; purchase storage is bigint, but its API intentionally stays safe-number. Neither legacy shape records an exponent or authoring-runtime provenance. Catalog revisions can retain the same exponent-less money shape historically.

A read-only local probe during this preflight found **Node v26.8.1 / ICU78.3 / CLDR48.0**, runtime162 currency options versus canonical165. CI config pins Node24 only; it does not prove the local ICU is the deployed historical runtime. The sixteen local scale differences are AFN, ALL, COP, HUF, IDR, IQD, IRR, KPW, LAK, LBP, MGA, MMK, PKR, SOS, SYP, YER: canonical2 versus ICU0, except IQD canonical3 versus ICU0. Runtime-only ANG/BGN/CUC/HRK/ZWL use ICU2, SLL uses ICU0, and XDR/XSU use ICU2 despite the current primary list's N.A. numeric units. These observations do not prove which exponent an existing record's author intended. No DB inventory or historical-runtime classification was performed or authorized here. An unmerged branch is not evidence of no external records.

Example: legacy `{amountMinor:100,currency:'AFN'}` currently presents100 with this ICU; canonical scale2 presents1.00. Both preserve the integer, but swapping the helper silently changes meaning. Multiplying it by100 to retain the current display guesses historical intent and alters stored data. XDR/XSU cannot honestly be assigned a canonical numeric exponent from the new map.

**Recommended smallest Task5 policy (L1): isolate the new valuation contract.** Keep existing purchase/custom/catalog wire shapes, accepted runtime currency set, safe-number bounds, stored integers and legacy helper semantics unchanged in this task. The values page neither displays nor imports their prices/helpers and never seeds a valuation from them. Route navigation adds no money round-trip or save. All new manual/external history uses explicit stored exponent and the canonical write parser. This introduces no reinterpretation and preserves existing read compatibility, including the eight runtime codes. It explicitly leaves the known legacy ICU interpretation and catalog floating display defects unresolved; do not label those legacy views canonical ISO or claim Task5 fixes them.

The smallest **separately approved numerical-only repair** would replace `catalog-facts`' Number division with the exact existing safe-integer-to-decimal legacy path and Intl presentation, using the same legacy scale semantics. It removes rounding loss without changing stored integers, but does not solve historical scale. Do not sneak this into the values formatter or use it to claim all money is repaired. Existing `minorUnits` comma-or-dot grammar must remain compatible if this optional repair is selected.

Alternatives and costs if root requires legacy canonicalization before UI delivery:

1. Freeze a legacy compatibility exponent table/runtime version and preserve old codes, then use it for future legacy writes/reads. This reduces future ICU drift but **does not establish past intent**, cannot classify externally authored numbers, and is itself a behavior change for browser/runtime cohorts that differed. It is acceptable only as an explicitly named legacy interpretation chosen by an operator/product ruling, not a recovered historical truth. N.A. codes stay legacy-only and never enter canonical valuation writes.
2. Add explicit optional exponent/interpretation-version metadata for legacy purchase, custom and catalog MONEY, plus write/read compatibility and an audited classification path. Existing rows remain unclassified with original integer/currency retained; an operator supplies evidence to assign scale. New canonical legacy writes can store scale. Historical catalog revisions cannot be rewritten casually; use immutable supplemental interpretation records or a separately designed revision policy. Unclassified records require a clearly labeled raw integer/currency view and restricted editing rather than a guessed major amount. Safe-number API bounds remain unless separately changed. This costs schema/native guards, DTO/read compatibility, every legacy editor, revision semantics, audit and scoped migration tests, well beyond the new page.

**Root decision L1 remains required:** accept the isolated Task5 delivery with the existing legacy defect explicitly carried, or require a separately scoped legacy-remediation task before implementation? If the latter, root must choose whether classified storage metadata is required, which operator/evidence may classify old records, how unclassified/N.A./retired currencies display/edit, and whether a frozen compatibility convention is an acceptable fallback. No automatic rescale, guessed historical metadata, current-ICU backfill, rejection of formerly readable values or blanket conversion is proposed. This is a narrow money-compatibility decision, not a Phase13 audit expansion.

## 5. Page content, source semantics and accessibility

Desktop uses cards with readable label/value grids; mobile stacks the same semantic order without horizontal page overflow. One h1 (“Wertverlauf / Valuation history”), a back-to-item link, item title, quantity and persistent “pro Stück / per unit” explanation. Context title is owner-only convenience; authoritative lifecycle/quantity/catalog state comes from the summary. Use `<section aria-labelledby>`, heading hierarchy, `<ol>` history rows and `<dl>` facts rather than a wide table requiring sideways scrolling. Long identifiers, notes and URLs wrap. Use actual buttons/links, visible focus, associated labels/help/errors and keyboard-operable native details. Scope changes use a labeled select or radio group, not color-only tabs. Status uses polite `role=status`; errors use `role=alert` once, without repeatedly announcing the entire history. Loading disables only the affected actions.

1. **Latest personal estimate** shows `manual.latest` independently of the current history page. Null says “Noch keine eigene Schätzung / No personal estimate yet”; zero is a visible exact amount. Timestamp and note remain private. Label latest by observation time. A newly added backdated record must not overwrite the later latest point. No sum or average card.
2. **Personal history** shows exact amount/currency, observation time, recorded/created time and note per row. Label order “Neueste Beobachtung zuerst / Newest observation first”. Historical currency changes remain distinct rows; no history-derived currencyConflict shortcut. Explain quantity split leaves history on its source item and does not create a new-item valuation. No edit/delete buttons for immutable history.
3. **Append form** for ACTIVE only. For ARCHIVED/DISPOSED show a specific read-only explanation and history; do not hide data or offer a form that merely fails. Quantity>1 is valid here; do not inherit grading's quantity=1 restriction.
4. **External sources** has explicit default CURRENT_MAPPING (“Aktuelle Zuordnung / Current mapping”) and opt-in HISTORICAL_MAPPING (“Historische Zuordnungen / Historical mappings”) for the still-current exact catalog target. Explain historical scope includes retained eligible facts for old mappings, not the item's previous links, and does not imply current mapping validity. No automatic fallback when current is empty. Show catalog entry link/exact variant identity when supplied, current revision and variant-active status; do not fetch a guessed title/variant by searching.
5. Each source group heading identifies providerId, localized kind and currency. Show namespace/type/externalId mapping in its details. Initial rows come directly from `history`; do not promote the first row into “market value”. Each row retains sourceMetric and every qualifier (including boolean false), point/range, sourceReference, sourceUrl and confidence fields (including sampleSize0). Render provider-authored labels/methodology faithfully as source statements, not our confidence claim. Links use allowed URL from the strict contract, `target=_blank rel="noopener noreferrer"`, meaningful label and visible destination host. Missing link/reference stays absent with no invented source URL.
6. Show observed time with SOURCE/FETCH basis, fetched time, recorded time (not a commit time), precision and catalog-match metadata. DAY renders UTC calendar date only, SECOND no fractional digits, MILLISECOND three fractional digits. `time dateTime` retains canonical original; details can expose exact canonical UTC. FETCH says explicitly “Quellzeit nicht angegeben; Abrufzeit verwendet / Source time not supplied; fetch time used”. Do not label fetched time as sold time or invent freshness from age. Catalog flags distinguish revision changed, identifier record replaced, mapping retired and variant retired. Replaced UUID with same semantic identifier can remain current; retain original/current revisions and identifier IDs.
7. `currencyConflict=true` shows “Mehrere Währungen; keine Umrechnung / Multiple currencies; no conversion” and its actual scope: latest personal estimate plus all eligible external groups in the selected mapping scope. False is not proof of comparability. No blended number even for one currency, all zero, or visually identical qualifiers.

## 6. Exact bounded reads and state transitions

Use finalized strict response schemas at the browser boundary. `fetch` uses no-store and AbortController for reads; abort alone is not an authority guard. Keep immutable request context `{itemId, locale, scope, epoch, requestSequence, cursor/selector}` and apply result/error/finally only if still current. A read must not reset a mutation's busy/error/acknowledged state. A locale/item/unmount change increments epoch and cancels reads. Do not use `readAt` as an optimistic-concurrency version or compare client clocks.

Fixed UI request sizes: summary manualLimit20/groupLimit4; source-history limit20; summary seeds up to5 rows per source. Keep one manual page, one four-group directory page and at most one expanded source's20-row history. Buttons “Ältere Einträge / Older entries” and “Zum Anfang / Back to newest” replace a page; source directory uses “Weitere Quellen / Next sources” and “Erste Quellen / First sources”. No unbounded append, all-history fetch, infinite cursor stack or count-total display. Null nextCursor disables the next control. Deduplicate by immutable row ID when replacing/combining an ACK display with a fetched page. New/backdated concurrent inserts and retention mean paging is a live traversal, not a frozen export; refresh restarts it.

| Event | Required transition and invariant |
|---|---|
| Initial load / refresh | Loading → validated summary or explicit read error. Retry only GET. No stale data on item/owner change. Refresh clears paging cursors/expanded source and starts a new epoch. Existing same-item data may remain visibly marked out-of-date during a failed refresh; do not call it empty. |
| Manual older page | GET summary with manualCursor and current group cursor/scope; replace manual page; take latest from the independently returned `manual.latest`, never from page[0]. Apply whole successful summary coherently. |
| Next group page | GET summary with groupCursor and current manual cursor; replace directory, close prior expanded group, invalidate source request. Preserve selected scope; response updates latest/lifecycle too. |
| Expand / page source | Use emitted source selector and its cursor exactly; no rebuilding selection from titles. Independent source sequence; match item, scope and current catalog context. Keep one expanded source; unrelated source responses cannot replace it. |
| Scope switch | Increment epoch; clear group/source cursors and current source facts before fetching selected scope; reset manual page for a coherent summary. Preserve valid manual draft. Never show old CURRENT rows under a HISTORICAL label or vice versa. |
| Cursor stale409 | Clear relevant cursors/source selection, show mapping-changed message and perform at most one first-page summary refresh. If refresh fails, explicit error/retry; no retry loop. Malformed400 is error, not “end of history”. |
| Submit | Synchronous mutation ref prevents double-click before React rerender. Freeze validated body and captured inputLocale; disable form/local scope+paging/language actions. Increment epoch to invalidate older GETs. One POST only. Never retry POST automatically. |
| Valid201 ACK | Store returned valuation ID/exact row as acknowledged; clear the submitted draft so retry cannot append it again. Increment epoch, reset manual cursor, request authoritative summary. ACK is an inserted point, not proof it is latest. Display confirmed saved row separately until refresh reconciles; label backdated truthfully. |
| ACK then refresh failure | Show “Gespeichert; Verlauf konnte nicht aktualisiert werden / Saved; history could not be refreshed” and exact acknowledged row. Retry GET only. Retained summary is explicitly stale. Never relabel as save failure or repopulate an automatic retry body. |
| Known validation/cap/inactive error | No success message. Retain draft. Inactive409 establishes read-only immediately, invalidates older reads and refreshes; an older ACTIVE GET cannot restore append. Cap409 disables further append for that state with explanation. Stable validated4xx rejection is distinct from unknown write outcome. |
| Network loss, malformed201 or ambiguous5xx after send | State `outcomeUnknown`: disable resubmit, retain frozen draft separately, say save could not be confirmed and may have succeeded. Offer read-only refresh/check history. No idempotency key is invented; identical amount/time/note is not an identity match and absence from a bounded/backdated page does not prove failure. A matching row may help the person inspect but cannot clear ambiguity automatically. Explicit “Start a new entry (may duplicate the previous one)” may unlock a fresh draft after that explanation; never automatically replay the frozen request. |
| Unauthorized/hidden404 | Clear private page/ACK/source data and drafts; show sign-in or hidden/not-found state without response details. Treat navigation away while POST is in flight as possibly committed; abort is never described as cancellation. |
| Concurrent lifecycle/link/quantity change | Every endpoint reread is authoritative. Existing page has no lifecycle writes; a409 or fresh summary immediately closes append for inactive items. Newer request sequencing prevents prior responses from reverting that state. Another tab's change is learned on refresh/POST, not promised realtime. Link revision change resets external cursors; quantity never changes money. |

Use schema-checked error envelope/status mapping. Display stable localized code explanations and optional request ID for support, never server causes, raw SQL/provider payload or authentication details. No global fetch middleware or optimistic cache framework is needed.
