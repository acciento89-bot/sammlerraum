## 2. Exact request and response direction

Thin proposed `GET /api/v1/dashboard` accepts only decoded keys `text`, `f`, `lifecycle`; raw encoded query including `?` <=32768 UTF-8 bytes before decoding; reject duplicate/unknown keys, empty segments, malformed percent/UTF-8. ## 3. Counts and collection meaning

`selection.itemCount = count(*)` of the complete matched item relation, not displayed cards and not physical units. `selection.unitCount = coalesce(sum(i.quantity::numeric),0)::text` of that relation. Native positive integer quantity is real inventory multiplicity; quantity 20 is one row/twenty units. No duplicate join may multiply either measure.

`collections.ownedLiveCount` counts `Collection WHERE ownerId=actor AND deletedAt IS NULL` independently of item text/filter/lifecycle, including genuinely empty collections and collections with only deleted/nonselected items. Name and label explicitly as all live owned collections. `selection.matchedCollectionCount` counts distinct collection IDs among matched items, thus zero for empty matches. Never label that as total collections. Collection filters do not magically attach empty collections to an item match. CollectionNode counts are not collection counts.

Largest collections rank only collections with matched items, by selected unit count DESC, selected item count DESC, collection ID DESC. Return id/name and both measures, labelled size within current selection. All-owned count still includes empty collections. Do not rank unknown-cost collections as zero value or compare different monetary denominations. An empty result legitimately returns item/unit/matched-collection counts zero, top lists empty, distributions with empty/fixed-zero buckets as appropriate; monetary no-data remains a separate state.
