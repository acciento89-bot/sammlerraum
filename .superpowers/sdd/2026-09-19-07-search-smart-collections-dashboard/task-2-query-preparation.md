FROM "CollectibleItem" i
JOIN "Collection" c ON c.id=i."collectionId" AND c."ownerId"=i."ownerId"
WHERE i."ownerId"=:actor AND c."ownerId"=:actor

## 4. AST → executable predicate matrix

All positive relation/value predicates return a nonnull boolean. A missing scalar comparison is false (`COALESCE(compare,FALSE)`); relation comparisons use EXISTS. NOT complements that boolean exactly and consequently includes absent/out-of-selector-scope items when its child was false. Never use nullable `<>`, `NOT IN` or “NOT EXISTS any row” in place of “NOT EXISTS a matching row.” Availability/reference checks happen before Boolean evaluation.

Exact DECIMAL operands canonicalize according to Task1 and producer (`search.ts:94–116`; custom-field-service.ts:153–164), bind strings as numeric, never lexicographic or float; INTEGER safe JS integers become bound bigint. - INTEGER: JSON number, integer grammar and safe-integer magnitude, then guarded numeric conversion. DECIMAL: JSON **string**, canonical exact decimal grammar with ≤20 integer/≤18 fractional digits/≤38 total, then numeric(38,18). ## 6. Cursor, route and error contract

Cursor proposal: canonical base64url UTF8 JSON `{v:1,contextHash,after:{createdAt,id}}`; strict keys, canonical timestamps/UUIDs, decoded ≤1536 bytes, round-trip base64url and fatal UTF8 checks. Stable key ordering, including record keys, and canonical scalar values are required; preserving logical child order is acceptable, no semantic commutativity rewrite needed. Direct context is null.
