## Behavior and decisions

- Added `GET /api/v1/media/:assetId/:variant` for lowercase `original`, `thumbnail`, `medium`, and `large`, dynamic and non-revalidated at the Next route layer. Invalid UUID/variant, missing or inaccessible asset/link/item, incomplete variant, and revoked reference return a generic no-store 404; no storage read occurs on denial. Inherited JavaScript object keys are not valid variants.
- The resolver reads server-owned asset/link/profile facts and uses the existing recursive `createResourceQuery.loadItem` for collection/node ancestry, missing/cyclic root rejection, owner matching, soft-delete exclusion, and archive/disposal checks. It checks every applicable live link. No request-supplied roles, inferred membership, or speculative catalog permission. A retained asset without a live item/document/avatar reference is inaccessible even to its owner; this follows the phase preflight and Task 5 revocation contract. Existing profile avatar reference is public because `PublicProfile` explicitly includes `avatarAssetId`; original remains owner-only. The owner must still have a live link/avatar reference.
- A document link's visibility is evaluated independently from item visibility, with all item and ancestor visibility required for public access. PRIVATE/UNLISTED receipts remain owner-only. The policy now rejects a protected document for a member role, rather than allowing a generic collection VIEWER to bypass the document protection bit. No collection memberships currently exist in the database.
- Public image bytes (IMAGE or image-backed DOCUMENT) come only from a complete selected READY WebP variant. Original image bytes are owner-only. Explicitly PUBLIC PDFs can use `original` with generic attachment filename `document.pdf`, `nosniff`, and `Content-Security-Policy: sandbox`; the stored filename never enters a header. READY, checksum, positive size/dimensions, and WebP MIME gate variants; UPLOADING and missing/reserved rows are denied.
- Authorization and current link/ancestor resolution precede `If-None-Match` handling. Strong checksum ETags and weak-match GET handling permit 304 only after current authorization; 304 never reads storage. Public responses use `public, max-age=0, must-revalidate` plus `Vary: Cookie`, because visibility can change without checksum or URL changes. Owner responses use `private, no-store`; errors use the wrapper's `no-store`. `apiRoute` preserves the success headers and adds request ID. A missing backing object maps to generic 404; unexpected storage failure remains generic 500.
